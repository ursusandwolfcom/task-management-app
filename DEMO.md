# Демонстрация ProjectFlow заказчику

Запустите приложение с профилем `alpha` по инструкции README и откройте
<http://localhost:8080/alpha/>. Нажмите **Открыть демо-сценарии**.
Демо добавляет недостающие проекты и сохраняет существующие данные и правки.
В свежем браузере сценарии уже есть в списке проектов.

1. **Клиентский портал.** Выберите Канбан в верхнем правом углу. Покажите четыре
   статуса, приоритеты, оценки длительности, сроки, зависимости и прогресс.
   Запустите и завершите «Реализовать личный кабинет»: «Проверить безопасность»
   станет доступна. «Запустить портал» останется заблокирована до завершения
   оплаты, безопасности, инструкций и исправления импорта.
2. **Восстановление сервиса.** Ошибка платёжного шлюза блокирует проверку заказов.
   Нажмите «Повторить», затем «Начать» и «Завершить». Проверка заказов откроется.
   Критический приоритет зависимой задачи не обходит зависимость.
3. **Очередь приоритетов.** Выберите порядок задач «Порядок выполнения».
   Серверный порядок ID: **4 → 2 → 3 → 7 → 1 → 5 → 6**.
   Среди доступных первым будет ID 4; ID 7 остаётся заблокирован до завершения ID 3.
   Равные приоритеты упорядочиваются по сроку, затем ID; отсутствие срока допускается.
4. **Проверки и удобство.** В редакторе задачи выберите зависимого потомка как
   предшественника: сервер отклонит цикл, форма и сохранённые данные останутся.
   Покажите поиск, фильтры, список/Канбан, плотность и три темы. Перезагрузка
   сохраняет проекты и настройки. Изменения во второй вкладке защищены от потери:
   устаревшая вкладка сообщает конфликт и требует перезагрузки.

Даты условные. Проекты, статусы и действия этого интерфейса — прототип в хранилище
браузера; порядок, готовность и следующий шаг рассчитывает настоящий Java `planning.core`
через `POST /alpha/plan`. Продолжительность отображается, но расписание пока не рассчитывается.

## Другие реализованные возможности бэкенда

Откройте <http://localhost:8080/swagger-ui/index.html>. В списке определений выберите
**identity** или **projects**; используйте отдельные тестовые аккаунты и полученный
JWT в **Authorize**, как описано в README. Не используйте реальные данные заказчика.

- **Identity:** регистрация и вход, собственный профиль, изменение пароля,
  сессии и выход; административное назначение роли требует ADMIN.
- **Projects:** создание и редактирование проекта, список доступных проектов,
  участники и передача владения. Данные сохраняются в PostgreSQL.
- **Доступ:** сравните владельца, участника и посторонний аккаунт; проверьте,
  что посторонний не может читать или менять чужой проект.

Эти API не связаны с локальными демо-проектами alpha. Серверный Task CRUD,
ресурсное расписание, Гант, критический путь, комментарии, вложения и уведомления
остаются будущими этапами и не входят в эту демонстрацию готовых функций.
